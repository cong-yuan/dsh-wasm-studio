## 1. 已完成(带验证)

### 1.1 组合 dsh 与 WASM 插件 ✅

Studio 持有 `cordis::Context`(dsh 的 base bundle:agent loop / sessions / tools /
llm seam)与 `WasmHost`。**每个 WASM slot 挂载为独立的 cordis 插件**——独立 fiber、
独立生命周期,`injects`/`provides` 是一等公民。

**验证**:`studio_boots_with_the_dsh_harness`、`shutdown_disposes_every_fiber_without_leaking`

### 1.2 插件生命周期与持久化 ✅

`load / unload / remove / set_enabled / reload / set_config / validate`,每一次变更
**原子写入** `studio.json`;启动时重放,所以 App 回来时还是你离开的样子。坏的或缺失的
持久化项被跳过,**永不致命**。

**验证**:`loading_a_plugin_persists_it_to_the_config_file`、
`enabled_plugins_autoload_on_next_boot`、`a_disabled_plugin_is_not_autoloaded`、
`a_broken_persisted_plugin_does_not_stop_boot`

### 1.3 热重载(stage-then-commit)✅

watcher(`notify`,mtime 兜底)盯着每个启用插件的 `.wasm`,重建后**就地热换**。
**原子**:新构建坏了就拒绝,正在跑的插件继续服务。拒绝会经
`studio://plugins-changed` 报到 UI。

**验证**:`the_watcher_hot_reloads_a_rebuilt_plugin`、
`a_broken_reload_leaves_the_running_plugin_intact`、`hot_reload_swaps_the_tool_surface`

### 1.4 前端槽位注册表 ✅

`src/lib/slots.ts` 是纯逻辑(无 Svelte 无 DOM),所以收敛规则可直接单测。三条规则:

1. **顺序无关**——先到先记,槽出现即挂载
2. **响应式**——槽消失则贡献隐藏但**记住**,槽回来即重现
3. **冲突是错误**——两个活插件不能开同名槽

**验证**(前端 45 个):`src/lib/slots.test.ts`,含"先到先记"与"卸载不丢贡献"

窗口带 **params**,经初始化脚本在组件挂载**之前**就位;窗口未开则排队。

**验证**:`a_plugin_can_declare_a_window`、`params_are_queued_until_the_window_opens`、

### 1.7d 重启后会话还在:读盘 + 续聊 ✅

§1.7c 只做了**写**。这一节做**读**,分两步(A 与 B),因为它们的代价差很多。

#### A. 列出来 + 看得到(`list_sessions`)

dsh 的 `SessionPersistenceApi` 有 `list()` 与 `load()`(公开),它的 CLI
`cmd_transcript` 就是这么读的。新增 `list_sessions`,返回**一个**诚实列表:
活着的 agent **在前**,磁盘上未加载的**在后**,行上用 `live` 区分。

三个设计上的决定,都不是随手写的:

1. **不重复列**。一个被恢复的会话同时是“活的”与“在磁盘上”。两个都报,
   用户就会为同一段对话看到两行,其中一行还是只读的。测试
   `a_stored_session_is_not_listed_twice_once_it_is_live` 钉住这点。
2. **行的投影复用 dsh 的 `Session`**,不是自己数一遍事件。把存盘日志当
   seed 构造 `Session`,拿到的标题/轮数/用量与它在活着的时期**完全一致**。
   自己写一遍就是 dsh surface 投影的第二个实现,注定会漂移。
3. **载入前先修**。进程被杀会留下一个未闭合的 turn。dsh 的 `fork` 对
   这种情况是**拒绝**;读路径的答案是 `repair_crash_turns`(公开),也就是
   dsh 自己的 `load_with_repair` 用的那个。先修再投影,行上的计数才与
   点进去看到的一致。

#### B. 续聊(`resume_session`)

**dsh 没有 resume 入口**。它的 CLI 能**读**一段对话(`cmd_transcript`),
但从不能**继续**一段。这一步是把 dsh 已经留好的零件装起来:

| 零件 | 作用 |
|---|---|
| `CreateSessionOptions.seed` | 文档写着 *"resume/fork/replay"* — 就是为这留的 |
| `Agent::new`(pub)+ `loop_driver::spawn_driver`(pub) | 把 session 挂成活的 agent |
| `dsh_rs::session::repair_crash_turns`(pub) | 补上崩溃留下的未闭合 turn |

关键在于 seed 的**语义是重放事件日志,不是重跑工具调用**。`Session::new`
把 seed 直接当初始日志,而 notifier 是在那**之后**才挂上去的——所以
seed 的事件**不会**被重新广播给持久化后端,也就**不会**在下次 flush 时
把整段历史再写一遍。这个 bug 在单个进程内**完全看不见**(内存里的
session 是对的),只有重启读文件才暴露。

专门为它写了 `resuming_then_restarting_does_not_duplicate_the_history`,
断言的是**重启后**重新读出来的历史(两次 `Studio::with_hook`),不是内存里的。

#### 顺手发现并修掉的两个真问题

**1. id 碰撞会**熔合两段对话**。** `SessionStore::mint_id` 是
**进程内计数器**且从 1 开始。Studio 是长时间运行的,而 `store_dir`
正是它的重点——所以重启后新建的会话会拿到 `session-1`,而 JSONL 后端是
**append** 的:新对话会被写进旧 `session-1.jsonl` 里。两段对话一个文件,
只能靠时间戳分辨。dsh 的 CLI 撞不上这个(每次都是新进程),Studio 会。
现在自动 id 用 `session-<ms>-<n>` 并逐个探测是否已被占用。

**2. 续聊的 agent 不在注册表里,所以关不掉。** `AgentRegistry` 只有
`create`(而且它**永远造空 session**),没有 `insert`。所以恢复出来的 agent
只能自己存(`Shared::resumed`)。后果是:`reg.dispose` 在它的 map 里找不到,
直接返回,**driver task 就永远跑着**——每个被关掉的会话泄漏一个任务。
`AgentRegistry::dispose` 其实**先**动手(设 `disposed`、cancel、wake)**才**
查 map,所以它对任何 `&Arc<Agent>` 都有效;用它。

#### 代价与诚实的边界

- **列盘扫描有缓存**。dsh **每个 token 都写一行** `AssistantChunk`,
  所以会话文件不小,而侧栏每 5 秒轮询一次。扫一次缓存住,本进程每次写
  (发消息/恢复/新建)时失效。
- **工作目录拿不回来**。`cwd` 存在 `SessionHeader` 里,而 JSONL 后端
  **只写事件、不写 header**。所以恢复后的会话没有 cwd。**不猜**
  (不填 `$HOME`/app-data):那会看起来像原来的,却把工具跑在别处。
- **模型配置能拿回来**。每个 turn 都会 append 一条 `RequestHeader`,
  里面有完整的 `LlmCallConfig`(provider/model)。所以恢复的会话继续对
  同一个 provider 说——用默认值会**静默**把对话换到另一个模型。

**验证**(后端共 66 个,新增 4 个):
- `a_restart_lists_the_sessions_that_were_written_to_disk`
- `a_stored_session_is_not_listed_twice_once_it_is_live`
- `resuming_a_session_restores_its_history_and_can_be_continued`
- `resuming_then_restarting_does_not_duplicate_the_history`

**前端**:`src/lib/commands.test.ts`(3 个)——断言**每个前端 invoke 的命令
后端都注册了**。这类漂移正好是这次问题的根源(前端在调 `list_agents`,
而会话能力早已齐全),以前没有任何东西比对过这两张表。测过:故意删掉
`commands::resume_session` 它**会红**。

## 2. 前端(Rust 侧的接缝)

Studio 用 Tauri **managed state**,持有的每个类型都是 `Send + Sync`(在宿主 crate
的测试里断言过),所以不需要包装体操。三条纪律:

- **guest 调用串行化**在 registry 互斥量之后,锁**从不跨 `.await`** 持有。
  挂载/卸载 slot 是 `async`(它驱动 cordis fiber);工具调用跳到 blocking pool。
- harness 跑在 Tauri 的**全局** async runtime 上——cordis 用 tokio task 驱动每个
  fiber,必须活得比 boot 久。
- slot 用 `WasmSlotPlugin::keeping_loaded` 挂载,所以 dispose fiber 只**停用**注册表
  里的 slot,**不销毁** guest 实例。这个分离正是热重载成立的原因。

## 4. 已知边界

- **同时只能有一个外壳**(`open:"startup"` 的唯一宣称者)。
- **`content: "html"` 窗口**靠初始化脚本注入;`content: "app"` 由路由渲染。
- **同步收敛**:`mount`/`unmount`/`reload` 里一次算完,不是异步滚动。
- **两个插件可同窗名不冲突**(label 带 slot 前缀),但**窗口标题**由插件声明。
- API key 明文躺在 `studio.json`——本地单用户 App 可以接受,**别同步那个文件**。
