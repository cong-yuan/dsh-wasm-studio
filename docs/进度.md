## 1. 已完成(带验证)

### 1.1 组合 dsh 与 WASM 插件 ✅

Studio 持有 `cordis::Context`(dsh 的 base bundle:agent loop / sessions / tools /
llm seam)与 `WasmHost`。**每个 WASM slot 挂载为独立的 cordis 插件**——独立 fiber、
独立生命周期,`injects`/`provides` 是一等公民。

**验证**:`studio_boots_with_the_dsh_harness`、`shutdown_disposes_every_fiber_without_leaking`

### 1.2 插件生命周期与持久化 ✅

`load / unload / remove / set_enabled / reload / set_config / validate`,每一次变更
**原子写入** `studio.json`;启动时重放,所以 App 回来时还是你离开的样子。坏的或缺失的
持久化项被跳过,**永不致命**。

**验证**:`loading_a_plugin_persists_it_to_the_config_file`、
`enabled_plugins_autoload_on_next_boot`、`a_disabled_plugin_is_not_autoloaded`、
`a_broken_persisted_plugin_does_not_stop_boot`

### 1.3 热重载(stage-then-commit)✅

watcher(`notify`,mtime 兜底)盯着每个启用插件的 `.wasm`,重建后**就地热换**。
**原子**:新构建坏了就拒绝,正在跑的插件继续服务。拒绝会经
`studio://plugins-changed` 报到 UI。

**验证**:`the_watcher_hot_reloads_a_rebuilt_plugin`、
`a_broken_reload_leaves_the_running_plugin_intact`、`hot_reload_swaps_the_tool_surface`

### 1.4 前端槽位注册表 ✅

`src/lib/slots.ts` 是纯逻辑(无 Svelte 无 DOM),所以收敛规则可直接单测。三条规则:

1. **顺序无关**——先到先记,槽出现即挂载
2. **响应式**——槽消失则贡献隐藏但**记住**,槽回来即重现
3. **冲突是错误**——两个活插件不能开同名槽

**验证**(前端 45 个):`src/lib/slots.test.ts`,含"先到先记"与"卸载不丢贡献"

### 1.5 插件窗口 ✅

插件可声明顶层窗口,三种打开时机:`manual`(插件自己开)、`auto`(激活时开)、
`startup`(**接管启动视图**)。两种内容:`app`(渲染插件组件)与 `html`(整页注入)。
窗口带 **params**,经初始化脚本在组件挂载**之前**就位;窗口未开则排队。

**验证**:`a_plugin_can_declare_a_window`、`params_are_queued_until_the_window_opens`、
`a_plugin_can_declare_a_self_contained_html_window`、
`the_html_window_bootstrap_escapes_its_payload`、`window_labels_are_sanitised_for_tauri`

### 1.6 启动视图由插件拥有 ✅

主窗口**建时即隐藏**,所以默认页永不先闪。启动时:有插件声明 `open:"startup"` 就开它,
否则开主窗口。**只有一个宣称者**——两个候选是**报错**而非抢跑。boot 若没能开出任何
窗口,则回退显示主窗口(绝不留一个无窗口的进程)。

**验证**:`a_plugin_can_declare_the_startup_window`、`two_plugins_cannot_both_own_the_startup_window`、
`a_plugin_that_only_uses_auto_does_not_claim_the_startup_window`

### 1.7 前端外壳 `hana-shell`(WASM 插件)✅

一个 WASM 插件(`plugins/hana-shell`,在姊妹仓库)接管启动视图,画出 HanaAgent 的
完整 chrome:**titlebar + 四栏**(sidebar / conversation / preview / rail),
**17 个槽**,四条边可拖。宿主 App 里**没有为它写任何特例**——它是普通插件。

**验证**:
- `a_shells_slots_are_visible_to_later_plugins`——`provides` 到达前端
- `a_later_plugin_may_fill_a_slot_it_did_not_open`——顺序无关
- `the_shell_slots_a_panel_mounts_are_the_ones_it_declares`——**双向**断言
  「manifest 声明的槽」==「JS 挂载的槽」
- `the_shell_ships_every_module_its_entry_requires`——资产齐全

### 1.8 插件贡献路由与侧栏项 ✅

`ui.routes[]` 声明一个页面(`path`/`component`/`title`/`icon`/`nav`),前端由
**一个** catch-all(`src/routes/[...plugin]/+page.svelte`)解析。路由与导航项是
**同一条记录**(同一事实的两个视图,分开写会漂移)。

**内置路径先解析**,所以插件无法遮蔽内置页——尝试遮蔽会被**明确拒绝**。

**验证**(前端):`src/lib/plugin-host.test.ts` 的路由冲突测试

### 1.9 插件可改造已有 UI ✅

`ui.adjusts`:`hide / unhide / replace / priority`,注册表级,可逆。冲突**可见**
而非静默解析——Settings 页列出所有生效中的调整及来源。

**验证**:`a_later_plugin_can_declare_adjustments_to_existing_ui`

## 2. 前端(Rust 侧的接缝)

Studio 用 Tauri **managed state**,持有的每个类型都是 `Send + Sync`(在宿主 crate
的测试里断言过),所以不需要包装体操。三条纪律:

- **guest 调用串行化**在 registry 互斥量之后,锁**从不跨 `.await`** 持有。
  挂载/卸载 slot 是 `async`(它驱动 cordis fiber);工具调用跳到 blocking pool。
- harness 跑在 Tauri 的**全局** async runtime 上——cordis 用 tokio task 驱动每个
  fiber,必须活得比 boot 久。
- slot 用 `WasmSlotPlugin::keeping_loaded` 挂载,所以 dispose fiber 只**停用**注册表
  里的 slot,**不销毁** guest 实例。这个分离正是热重载成立的原因。

## 4. 已知边界

- **同时只能有一个外壳**(`open:"startup"` 的唯一宣称者)。
- **`content: "html"` 窗口**靠初始化脚本注入;`content: "app"` 由路由渲染。
- **同步收敛**:`mount`/`unmount`/`reload` 里一次算完,不是异步滚动。
- **两个插件可同窗名不冲突**(label 带 slot 前缀),但**窗口标题**由插件声明。
- API key 明文躺在 `studio.json`——本地单用户 App 可以接受,**别同步那个文件**。
